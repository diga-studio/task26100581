# reviewplanner

质量材料评审派单规划库（Go）。上层直接在进程内调用，输入与规划结果均保存在内存中，无外部服务依赖。

## 功能

- 首次自动派评与对同一批材料的重新规划。
- 每份材料恰好分配 3 名不同评审员，且 3 人来自不同部门。
- 逐材料回避名单：名单中人员不会被派到对应材料（回避关系由上层确定，本库不推断）。
- 容量约束：每人 `已有在办量 + 本批次分配量 ≤ 总在办量上限`；已有在办量只统计本批次之外的任务，旧方案不重复计入。
- 人工锁定配对必须出现在最终方案中，但不能绕过回避、部门或容量限制；锁定可只覆盖部分席位，其余席位自动补齐。
- 两级目标（第一目标绝对优先）：
  1. 重排时保留最多旧方案中的材料-评审员配对；
  2. 所有评审员分配后总在办量的平方和最小（负载均衡）。
- 存在合规完整方案则返回完整最优方案，否则返回无解，绝不返回部分派评。

## 使用

```go
import "reviewplanner"

res := reviewplanner.Plan(reviewplanner.Input{
    Materials: []reviewplanner.Material{
        {ID: "M1", Avoid: []string{"R3"}},
        {ID: "M2"},
    },
    Reviewers: []reviewplanner.Reviewer{
        {ID: "R1", Department: "D1", BaseLoad: 1, MaxLoad: 4},
        {ID: "R2", Department: "D2", BaseLoad: 0, MaxLoad: 4},
        {ID: "R3", Department: "D3", BaseLoad: 0, MaxLoad: 4},
        // ...
    },
    Locks: []reviewplanner.Lock{
        {MaterialID: "M2", ReviewerID: "R1"},
    },
    // 重排时传入上一版完整方案；首次派评传 nil。
    Previous: nil,
})

if !res.Feasible {
    // 不存在合规完整方案
} else {
    // res.Assignments    完整派评配对
    // res.PreservedPairs 保留自旧方案的配对数（第一目标值）
    // res.LoadSquareSum  分配后总在办量平方和（第二目标值）
}
```

## 实现说明

建模为最小费用最大流：源点 → 材料（容量为剩余席位）→ （材料 × 部门）槽位（容量 1，保证同材料部门互异）→ 评审员 → 汇点（按边际平方费用拆成单位容量边，实现负载平方和最小化）。旧方案配对在候选边上携带一个大权重负费用，保证“保留最多旧配对”绝对优先于负载均衡。人工锁定在求解前预分配并校验，任何与回避、部门、容量冲突的锁定直接判无解。
